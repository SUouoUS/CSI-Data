# CSI-Data

> **CSILEEP / 도전학기 국제학술대회 연구**의 파일럿 데이터 분석 저장소

ESP32에서 수집한 Wi-Fi **CSI**(Channel State Information, 신호가 송수신되며 겪은 채널 변화 정보)를 분석한다.
현재는 **파일럿 단계**이며, 본수집에 앞서 측정 배치와 프로토콜을 확정하는 것이 목적이다.

---

## 1. 프로젝트 목표

최종 목표는 두 가지다.

1. **`empty` / `still` / `motion` 3상태 분류** — 비재실 / 재실·정지 / 움직임
2. 그 위에서의 **bed-exit event detection** — 침대 이탈 이벤트 검출

> [!NOTE]
> 호흡 분석은 이 연구의 목표가 아니다.
> `empty`와 `still`의 분리가 약해서 **추가로 탐색한 특징 후보 중 하나**일 뿐이며,
> 호흡 reference sensor로 검증한 적이 없으므로 "호흡 검출"이라고 부르지 않는다.

---

## 2. 측정 환경 및 CSI 구조

> 이 절의 내용은 **기술 검증이 끝난 사실**이다. 실험 결과(4절 이후)와 구분해서 보면 된다.

ESP32 2대(TX–RX), 802.11n **40 MHz**, channel 11, 약 **19 Hz**, **session**(한 번의 연속된 측정) 당 5분.

CSI 한 프레임은 `len = 384` byte = 192 complex이며, 실측 널 패턴으로 **LLTF(64) + HT-LTF(128)** 구성임을 확정했다.
분석에는 HT-LTF의 유효 **subcarrier**(Wi-Fi 채널을 구성하는 세부 주파수 성분) **114개**(±2 … ±58)만 사용한다.

<details>
<summary>블록 구성 판정 근거</summary>

`len=384`는 `20 MHz + STBC`(64×3)로도, `40 MHz + non-STBC`(64+128)로도 해석된다.
메타데이터가 `bandwidth=1`, `stbc=0`이고, index 64–191을 128-bin FFT로 풀었을 때
널 패턴이 802.11n HT40 규격과 정확히 일치하므로 후자로 확정했다.

```
sc  0        (idx 64)              1.6      → DC null
sc ±2 … ±58  (idx 66–122,134–190)  30–43    → 유효 (114개)
sc ±60… ±64  (idx 124–132)         0.6–1.4  → guard
```

또한 `first_word = 1`이므로 버퍼의 **첫 4바이트는 하드웨어 버그로 무효**다.
전 프레임 상수값 `47, -16, 2, 0`이 나오며 마스크에서 제외한다.

</details>

## 3. 현재 파일럿 데이터

파일럿 **10세션**. 상태 라벨은 `still` / `empty` / `motion` 셋이다.

| 파일 | 구성 | 비고 |
|---|---|---|
| `P01_stable` `P02_stable` `P03_stable` | still 5분 | 피험자 3명 |
| `P01_motion` `P02_motion` `P03_motion` | still 2분 → **motion 1분** → still 2분 | 15초 간격 동작 4회 |
| `empty1` `empty2` | empty 5분 | |
| `stable_5min` `empty_5min` | still / empty 5분 | 선행 수집 (배치 A) |

> [!WARNING]
> 선행 수집 2개(배치 A)는 나머지 8개(배치 B)와 캡처 조건이 다르다.
> 수신률 17.5–18.1 Hz vs 19.1–19.4 Hz, 프레임 손실 **7.7–10.7 %** vs **1.1–2.7 %**.
> 섞어 쓰면 배치 효과가 상태 효과로 오인될 수 있다.

## 4. 분석 원칙

- **독립 표본의 단위는 프레임이 아니라 session이다.** 한 세션의 수천 프레임은 자기상관 때문에 표본 1개다.
- **정확 순열검정**(라벨을 가능한 모든 방식으로 뒤섞어 관측값이 얼마나 특별한지 보는 방법)을 쓰고, 표본 수만으로 정해지는 **도달 가능한 최소 p를 항상 함께 출력**한다.
- 임계값은 **`empty` 세션에서만** 정한다. 점유 데이터로 정하면 순환논증이다.
- 효과크기 분모는 **세션 간 pooled SD**, subcarrier 스크리닝에는 **BH(FDR) 보정**(여러 특징을 동시에 검정할 때 우연히 유의하게 나오는 결과를 줄이는 보정)을 적용한다.
- 윈도우 중첩 금지.

> [!IMPORTANT]
> **`p < 0.05` 달성 자체를 목표로 하지 않는다.**
> 표본 수가 매우 작은 파일럿이므로 p값과 **sep**(두 상태의 분리 정도)는 **탐색 단계의 참고 지표**이며,
> 최종 통계적 결론이 아니다.
> 이미 분석한 데이터에서 filter · window length · frequency band를 반복 변경해
> 좋은 p값을 찾는 방식은 쓰지 않는다. 파일럿에서 나온 가설은 **새로운 반복 데이터로 검증한다.**

## 5. 확인된 결과

**기술 검증**

- CSI 블록 구성, 유효 subcarrier mask, `first_word` 무효 구간을 실측으로 확정했다.
- 10세션 모두 무결성 검사(`s1`)를 통과했다. 파싱 드롭 0건, 1초 이상 공백 0회.
- 배치 A와 배치 B의 캡처 조건 차이를 정량적으로 확인했다.

**파일럿 관찰 — `motion` vs `still`**

세션 **안에서** `still` 구간과 `motion` 구간을 비교했다. 같은 세션·같은 사람이므로 환경 차이가 상쇄된다.

- **114 / 114 subcarrier**가 피험자 3명 전원에게서 같은 방향으로 반응했다 (우연이라면 25 % 기대).
- 시간 표준편차가 `still` 0.0267 → `motion` 0.0363으로 **+36 %** 증가했다.

방향 일관성은 뚜렷하지만 대조 가능한 세션이 3개뿐이라 순열검정의 최소 p가 0.25다.
**관찰은 일관되나 통계적 확증에는 반복이 더 필요하다.**

**방법론적 확인**

- "여러 subcarrier의 피크 주파수가 일치하면 호흡"이라는 판별 방식은 **쓸 수 없다.** `empty1`에서도 일치율 100 %가 나온다. 인접 subcarrier는 채널 상관 때문에 잡음 피크도 함께 움직인다.

## 6. 검증이 필요한 결과 / 가설

### `empty` vs `still` 분리

**현재 파일럿 데이터와 지금까지 시도한 특징에서는 안정적인 분리를 확인하지 못했다.**
다른 특징이나 ML 분류기를 포함한 최종 분류 가능성까지 기각된 것은 아니다.

- 진폭 프로파일은 상태와 무관하게 세션 간 코사인 유사도 0.994 – 0.9995로 거의 동일했다.
- 시도한 특징 8개 중 7개가 sep ≤ 1.33에 머물렀다.

### `lowfreq_ratio` (0.01 – 0.1 Hz 전력비)

여러 특징을 탐색하는 과정에서 나온 결과 중 하나다. 완전 분리를 보였고 p = 0.0286이었으나,
**BH(FDR) 보정 후 p = 0.229로 유의하지 않다.** 현재는 **재현이 필요한 탐색적 결과**로만 둔다.

### 호흡 가능성이 있는 주기 성분

일부 세션에서 호흡일 수 있는 주기 성분이 관찰되었다. `breath_snr_max`(**SNR** = 신호가 잡음보다 얼마나 뚜렷한지 나타내는 값)의 세션별 값은 다음과 같다.

| 세션 | 상태 | `breath_snr_max` |
|---|---|---|
| `P03_stable` | still | 14.70 |
| `P02_stable` | still | 10.31 |
| `A_stable` | still | 9.71 |
| **`empty1`** | **empty** | **8.24** |
| `P01_stable` | still | 5.88 |
| `A_empty` | empty | 5.44 |
| `empty2` | empty | 4.55 |

재실 4세션 중 3세션이 모든 비재실 세션보다 높았으나, **`P01_stable`(5.88)이 `empty1`(8.24)보다 낮다.**
`breath_snr_max`는 기존 PC1 기반 특징보다 분리도가 개선되었지만,
**참가자·세션 전체에서 안정적인 점유 판별 특징이라고 결론내릴 수 없는 상태다.**

- `P02_stable`에서 0.273 Hz(약 16.4회/분) 피크가 세션 전후반에 걸쳐 유지되었다. **호흡 후보**이며, reference sensor 검증은 하지 않았다.
- `P03_stable`은 SNR이 가장 높으나 피크 주파수가 0.156 → 0.293 Hz로 변동해 **현재 분석에서는 호흡으로 판단하기 어렵다.** 이는 P03의 CSI에 호흡 정보가 없다는 뜻이 아니다.

## 7. 현재 한계

- 세션 수가 적다. 조건별 반복이 1–2회뿐이라 **참가자 차이와 세션 변동을 분리할 수 없다.**
- `breath_snr_max`는 분석 창 길이를 280초 → 105초로 바꾸면 피험자 순위가 뒤집힌다. **측정 조건에 민감하다.**
- 배치 A와 B가 섞여 있어 배치 효과를 통제하지 못한다.
- 호흡 관련 해석을 검증할 **reference sensor가 없다.**
- `motion` 대조가 3세션뿐이라 최소 도달 가능 p가 0.25다.

## 8. 파일럿 2에서 확인할 질문

sep나 p값을 높이기 위한 실험이 **아니다.** 본수집 전에 배치와 프로토콜을 확정하기 위한 실험이다.

- `P02`에서 관찰된 호흡 후보 특징이 **반복 세션에서도 재현되는가?**
- `P01`의 낮은 값이 **다시 나타나는가?**
- **참가자 차이와 세션 변동 중 어느 영향이 큰가?**
- `empty` 세션의 특징은 **반복 측정에서도 안정적인가?**
- 새 배치를 쓴다면 기존 배치보다 **`empty`/`still` 구분의 재현성이 실제로 좋아지는가?**

**구성** — 피험자당 3회, `empty` 3회로 총 12세션(60분).
무작위 완전블록으로 순서를 배치해 조건과 시간의 교락을 차단한다.

```
1~4    P02   empty  P01   P03
5~8    empty P03    P02   P01
9~12   P03   P01    empty P02
```

### TX / RX 배치 (후보)

두 기기를 잇는 경로 근처에 가슴이 오도록 두면 **호흡에 의한 미세 움직임이 CSI에 더 잘 반영될 가능성이 있다.**
이는 아직 검증되지 않은 **후보 배치**이며, 반드시 그래야 한다는 조건이 아니다.

> [!CAUTION]
> 새 배치를 적용한다면 기존 batch와 **같은 조건으로 섞지 않는다.**
> `sessions.py`의 `batch` 필드에 새 라벨을 주어 별도 조건으로 수집하고,
> 파일럿 2에서 재현성을 비교한 뒤 본수집 배치를 하나로 확정한다.

## 9. 본수집으로 넘어가는 기준

아래가 정리되면 배치와 프로토콜을 하나로 확정하고 본수집에 들어간다.

- [ ] 참가자 내 반복 변동과 참가자 간 차이의 크기를 비교할 수 있다 (반복 3회 확보)
- [ ] `empty` 세션의 특징 분포가 반복 측정에서 안정적이다
- [ ] 파일럿 1에서 나온 가설(호흡 후보, `lowfreq_ratio`)의 재현 여부가 판정되었다
- [ ] 배치를 비교했다면 어느 배치가 재현성이 높은지 결론이 났다
- [ ] 위 결과로 **배치 1개 · 프로토콜 1개**를 확정했다

## 10. 실행 방법

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install numpy scipy matplotlib
```

```bash
python s1_check_format.py     # 반드시 먼저. FAIL이면 여기서 멈춘다

python s3_subcarrier.py

```

| 스크립트 | 판정하는 것 |
|---|---|
| `csi_core.py` | 파싱 · 전처리 · 특징 · 세션단위 통계 (전처리는 여기에만 둔다) |
| `sessions.py` | 세션 매니페스트 + 전역 설정 |
| `s1_check_format.py` | 분석을 시작해도 되는가 |
| `s2_session_stats.py` | 특징이 상태를 가르는가 |
| `s3_subcarrier.py` | 어느 subcarrier가 반응하는가 |
| `s5_pilot_check.py` | 본수집 조건을 어떻게 확정할 것인가 |

결과물은 전부 `out/`에 저장된다. 새 세션은 `data/`에 넣고 `sessions.py`의 `SESSIONS`에 한 줄 추가하면 된다.

```python
{"name": "b2_01_P02", "scenario": "S-1", "file": "b2_01_P02_stable.txt",
 "subject": "P02", "batch": "B2", "segments": [("still", 0.0, 299.0)]},
```
